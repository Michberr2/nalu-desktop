Build a complete working full-stack website called Fieldwork, a single-user project task dashboard, in this Vite/React project. Implement the files, run the build and real API tests, and finish with actual results. Work only inside this project. React, React DOM, Vite and lucide-react are installed through node_modules; use Node built-ins for the backend, with no dependency installs or other coding agents. Do not deploy or contact external services.

The UI must be a polished responsive dashboard at 390px and 1440px: sidebar/header navigation, overview summary counts, task list and kanban views, search and status/priority filters, an empty state, create/edit task forms, status changes, and a delete confirmation. Use a restrained indigo/slate palette, clear hierarchy and spacing, local icons/visuals, visible labels, keyboard-accessible controls and no horizontal overflow. Show loading, saving and API errors. Edits must persist in the backend, not just localStorage. Include a clear local single-user demo notice; do not claim authentication or multi-user security.

Implement server.mjs using Node HTTP. It serves the production dist directory and the API below on 127.0.0.1, respecting PORT (default 4180). npm run build builds the frontend; npm start starts server.mjs. The server must support reloading frontend views. Store data in a JSON file selected by DATA_FILE (default .data/tasks.json), creating parent directories. Persistence must survive restart. Writes must be serialized/atomic enough that simultaneous creates are not lost. No frontend-only fake API responses.

API contract:
GET /api/tasks returns {tasks:[...]}, initially empty, in creation order.
POST /api/tasks with JSON {title,description?,status?,priority?} returns 201 and {task:...}. Generate a unique string id and ISO createdAt timestamp. title is required, trimmed, 1..120 characters; description defaults to empty and is at most 2000 characters; status defaults to todo and must be todo, doing or done; priority defaults to medium and must be low, medium or high. Do not silently coerce invalid field types.
PATCH /api/tasks/:id validates and changes only supplied fields; preserve id/createdAt and other fields. Return 200 and {task:...}. Reject invalid or empty title/status/priority and unknown writable fields. Missing id returns 404.
DELETE /api/tasks/:id returns 204 with no body; a missing id returns 404.
Malformed JSON or invalid fields returns 400 with {error:string}, leaving stored data unchanged. Unsupported methods on existing API routes return 405; unknown API routes return 404. Oversized request bodies above 64 KiB return 413. An invalid request must not crash the process. Error responses must be JSON. User-provided text must render as text, not executable HTML.

The browser must let users create a task, edit its title/description/priority, move it between all statuses, search/filter it, cancel and confirm deletion, and see correct counts. Required-field validation should prevent accidental invalid submission. A page reload must show server data. Document run/build/test commands, architecture and demo limitations in README. Verify successful CRUD, invalid inputs and restart persistence using a temporary DATA_FILE without modifying the user's files.
